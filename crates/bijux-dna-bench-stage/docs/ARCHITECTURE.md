# Stage ownership and features

`model/` owns persisted records and schema definitions; `validation/` owns semantic
admission. Benchmark-model compatibility aliases retain wire identity and translate
canonical reasons into its existing policy-error taxonomy. There is one schema authority.

`repository/` reads FASTQ/BAM matrices and accepts normalized VCF rows from its existing
domain adapter. It validates complete inventory selections before creating outputs.
`execution/` projects primary-tool plans with checked GiB-to-MiB conversion and uniform
resources. The CLI supplies canonical planners and native materializers.

Scripts use structured argv and resolve their source repository at the actual nested
output depth. Internal scripts relocate with the repository; external scripts retain
an explicit absolute source root. Persisted commands retain the public Cargo invocation.
Compiled executable reuse is a separate execution contract, not a claim made by this owner.

Synthetic output fixtures preserve the established placeholder payloads. They are file
shape evidence only. Existing different bytes, symlinks and conflicting kinds are refused
rather than removed. Publication admits every destination before writes but does not
provide a multi-file transaction or protection against concurrent namespace replacement.

The new default native dependency closure has no workspace crates. Optional execution
adds core, infrastructure and stage contracts; repository adds infrastructure only.
Wall-time and rebuild savings require measured edit cohorts; dependency isolation alone
is not a CI-under-ten-minutes result.

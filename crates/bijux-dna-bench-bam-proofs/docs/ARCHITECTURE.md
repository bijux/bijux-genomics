# BAM scientific proof architecture

Readiness declarations and scientific completion are separate compilation owners.
The four-method declaration port returns existing canonical reports. The eight-operation
native port retains exact smoke-writer identity and requires an admitted explicit root.
The CLI adapter refuses root disagreement before native effects, without changing process
working directory or global environment variables.

Each capability contains persisted public models, private native observations, declarations,
output acquisition, scientific predicates, explanatory diagnostics, row projection and
publication. Domain BAM retains existing typed summary and parser authority. This owner
has no native API, planner, runner, frontend or benchmark umbrella dependency. Its BAM
domain dependency remains real; this split does not claim a contract-only Cargo closure.

Acquisition order, case selection, numerical tolerances, sample/reference identities,
coverage/insufficiency behavior and published schemas retain their existing contracts.
Publication retains failed assessments before returning their domain-specific errors.
Atomic replacement applies per report, not transactionally across provider effects.

Genotyping and kinship use `DownstreamContext` to consume parser snapshots, pipeline
nodes, VCF count/missingness observations and canonical kinship readiness. These are
nonserialized inputs containing exactly the evidence used by the scientific assessment.
The CLI projects the canonical providers without sorting, filtering, deduplicating or
inventing values. Pipeline admission and the retained checks remain their respective
authorities; canonical serialized pipeline/parser/VCF models are not duplicated here.

The `bam_downstream` feature activates these two scientific services and the existing BAM
evidence feature. Disabled builds retain their explicit feature requirement before any
provider effects. No extra normal, dev or build dependencies are introduced.

Retained-tool completion groups binding identity, provider evidence acquisition, scientific
stage completion, aggregate conditions and report publication. `RetainedContext` supplies
three independent provider contracts: binding evidence, qualification evidence and exact
stage proof identity. Five canonical BAM declaration reports enter unchanged. Other
providers expose only consumed nonserialized observations; adapters preserve full row
sequences until the owner derives the retained BAM binding sets.

The CLI composition admits the requested canonical root before any provider or output
effects. Neither owner nor composition changes the working directory. Stage failures
remain individual diagnostic checks, allowing later checks to run; acquisition failures
still stop before aggregate replacement.

Genotyping and kinship separate filesystem publication paths from serialized relative
paths. Both resolve writes against the explicit request root, even when their caller's
working directory is a crate directory. Absolute requested destinations remain absolute.

Kinship requests its canonical parser observation directly. Its admission still checks
the king binding and scientific snapshot, but unrelated FASTQ/VCF parser execution
and the all-family report are not prerequisites of the kinship proof. The all-family
parser command remains responsible for complete parser coverage.

## Tiny parser proof producers

`parser_probes/` owns alignment, contamination, damage, authenticity, genotyping,
kinship and sex tiny proof generation. Callers pass typed inputs projected from
canonical configuration; no planner or CLI dependency enters this owner. `reports`
selects retained canonical BAM parsers. Synthetic scalar estimates retain their
parser-fixture meaning and do not claim backend execution or scientific accuracy.

Parser alignment requests admit only canonical BWA or Bowtie2 backends before
reading inputs or creating output directories. Contamination requests carry the
canonical typed scope and share domain tool/scope admission with the planner.
Generated method and observed tool identity agree; unknown tools never select a
fallback implementation. Synthetic estimates still establish parser behavior only.

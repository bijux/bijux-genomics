# Workflow boundaries

The workflow owner sequences retained stage operations and assembles their reports.
Corpus/truth admission belongs to `bijux-dna-bench-corpus`. Scientific stage
execution stays in domain/stage owners. The CLI selects fixture implementations
and acquires tool bindings; the workflow never calls back into CLI or API routing.

Each family groups wire/internal artifact models, stages, handoff evaluation,
observations and filesystem operations. Common output admission validates every
prior declared path before retiring generated files and preserves unknown files.
This is explicit output ownership, not transactional execution: an admitted run
may fail after retiring its previous declared generated outputs.

Existing deterministic fixture timings, semantic runtimes and skipped stages retain
their original report classifications. Local fixture success does not prove native
tool interchangeability, hosted performance or fresh remote campaign execution.

The amplicon default feature does not compile alignment or variant domains.
The `genomics` feature admits those owners for germline and ancient-DNA workflows.
Alignment fixture operations explicitly distinguish SAM from BAM; tool binding
admission requires exactly the four germline VCF stages before execution begins.

Stage execution, handoff bindings, truth assessment and report publication have
separate owners within each workflow. Completed amplicon stages pass a typed
artifact set to judgment; report projections derive output paths and metrics
from the published stage evidence. A single-ended primer sample rejects paired
or mate-bearing smoke evidence before copying outputs. Independent observation
booleans retain their persisted fields, and approximate numeric metrics retain
their existing floating-point semantics and separate integer observations.

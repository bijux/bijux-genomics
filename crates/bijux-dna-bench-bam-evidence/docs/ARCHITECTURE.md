# BAM evidence architecture

`command_coverage` classifies support, adapter, parser and corpus gaps.
`parser_coverage` projects admitted benchmark-ready rows into declaration coverage.
`output_contract` interprets canonical planner observations and retains failure reasons.
`report_map` owns seven report sections, anchor selection and exact expected identities.
`consistency` compares six surfaces with the active binding set, retaining multiplicity.

Each capability keeps its models, service, projection/admission and publication near
one another. Private modules are not public extension points. `observations` holds
only consumed, nonserialized fields; `ports` separates canonical acquisition authorities.
Shared cross-domain serving and expected-result schemas keep their existing authority.
No native BAM or planner dependency is needed to compile or test this evidence owner.

A report-map request acquires inventory, admissions and expected rows once. A later
request reacquires them; no process-global cache can conceal evidence drift. Nested
provider operations retain their existing acquisition responsibilities. Other compound
surfaces may still reacquire nested inputs and are not claimed globally deduplicated.

Output paths resolve against the explicit repository root, including consistency
reports. TSV and JSON replacement is atomic per file, not a transaction over provider
publications. Invalid report identities reject before replacing the report. Failed
consistency assessments publish all six diagnostics before returning an error.

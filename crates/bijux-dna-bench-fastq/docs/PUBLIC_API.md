# Public API

`probes` consumes typed `StagePlanV1` inputs and returns `MaterializedFastqProof`. Correction also requires explicit read paths, quality encoding and conservative-mode settings. Five producers own reference indexing, correction, host depletion, rRNA depletion and taxonomy fixtures. `probes::reports` selects fifteen canonical FASTQ domain report parsers and returns the JSON value from the same input observation after typed admission.

Stage identity and required input observations are admitted before fixture creation. Read framing checks cover four-line completeness, header/separator markers and matching sequence/quality lengths; they do not establish biological validity or paired-read identity. Publication is atomic per file and accepts existing gzip input without recompression. Synthetic unchanged and empty outputs establish parser compatibility only.

`readiness::inputs` defines explicit serving snapshots and active-scope rows. `readiness::{adapters,active,parsers,fixtures}` each owns collection and report publication. Persisted report models and enum labels retain their serialized identities. Only comparable, benchmark-normalized and parse-normalized parser states establish normalization; arbitrary status strings do not. Duplicate bindings and inconsistent declared cardinalities reject before publication. Fixture-coverage diagnostics are published even when governed fixture evidence is missing, then the service returns an error.

`readiness::{output_contract,report_map,commands}` retains ten existing wire/model surfaces and publishes their governed TSV, shell and argv JSONL outputs. `readiness::declarations` exposes capability-specific contexts and canonical observation ports. Output-provider failure remains an incomplete output-contract row; missing or extra command bindings refuse before publication. Report placement preserves complete result identity, six sections, seven summary tables and the admitted default/support ordering.

`proofs::{validate_reads,trim_stages,filter_stages,duplicate_stages}` publish evaluated reports through explicit `SchemaContext` or `ValidationContext`. Composition supplies canonical sources, native smoke materialization and evidence addresses; output paths are borrowed.

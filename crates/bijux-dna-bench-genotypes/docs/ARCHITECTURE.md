# Genotype benchmark boundaries

The composition edge supplies `GenotypeBenchmarkInputs`; catalog acquisition does
not belong to these services. Input admission rejects foreign/duplicate stages,
wrong canonical adapter/parser IDs, unsafe tool identities and malformed outputs.
Family admission verifies the retained tool, corpus, asset profile and output role
before scientific fixture acquisition or output creation.

BAM validation belongs to the corpus alignment feature. `bam::execution` owns real
reference materialization, explicit calling modes and native `CallStageOutputs`.
Scientific observations retain genotype, missingness, likelihood and replay semantics.
The existing calling and GL wire schemas are imported directly from bench-model;
the other family schemas live beside their owning observations and projections.

Native executions remain at immutable physical paths. Stable output indexes are
projected by bench-artifacts; native manifests, compressed payloads, checksums and
replay products are not rewritten. Unknown files are preserved and unowned output
replacement fails. Prior executions remain until dependency-aware retirement is
available. Multi-file publication is not transactional. Concurrent publication to
one destination is unsupported; the compatible call alias retains its nonblocking
publish lock.

Pseudohaploid replay compares canonical VCF payloads after excluding existing
bcftools command headers. Its recorded control seed is report metadata; the retained
deterministic first-allele projection does not pass it as a random tool parameter.
This contract does not assert stochastic sampling or equivalence to another caller.
